### КРИТИЧЕСКОЕ ОБНАРУЖЕНИЕ: формулы потеряны при конвертации
В исходном HTML все математические выражения — это картинки MS Equation
(`chap2_10.files/imageNNN.gif`, только в главе 2.10 — 191 `<img>`), а сами `.files/`-каталоги
с gif-файлами в архив НЕ включены. При извлечении текста символы формул выпадают:
в строке вида «…получаем окончательно . (2.10.3)» остаётся лишь номер, а выражение пропало.
Текстовые связки («где σт — предел текучести…», таблицы коэффициентов) сохранились полностью,
поэтому каждую формулу можно восстановить по контексту — точно так же, как было сделано
для глав 1.1–1.3 в первом прогоне.

## 2. Стратегия модернизации

### Этап 0. Инфраструктура (0.5 дня)
- `strength_core` → превратить в пакет с подобластями:
  ```
  strength_core/
      core/         # общие примитивы: интегрирование, интерполяция, квантили, оптимизация
      fem/          # I/O полей МКЭ (VTK/Ensight/HDF5), структура Node/Element/Field
      ch1_stats.py / ch1_tolerance.py / ch1_reliability.py   # текущие модули (мигрировать)
      ch2_mechanics/  # 2.2–2.9: сопромат
          tension.py (2.2), sections.py (2.3), torsion_shear.py (2.4),
          bending.py (2.5), deflections.py (2.6), stress_state_criteria.py (2.7),
          cylinders_shells.py (2.8), stability.py (2.9)
      ch2_fatigue.py    # 2.10 — самое ценное для МКЭ-ядра
      materials_db.py   # 2.11 — таблицы материалов (JSON/parquet), не функции
      criteria.py       # 2.12 — критерии работоспособности, запасы
      ch3_elasticity.py # 3.1; ch3_contact.py (3.2); ch3_approx_methods.py (3.3)
      ch3_vibration.py  # 3.4.1–3.4.2
  ```
- Единый реестр формул `docs/formula_registry.csv`: глава, номер, имя функции, статус
  (`restored`/`implemented`/`tested`/`blocked`) — по нему отслеживаем покрытие ~537 формул.

### Этап 1. Восстановление формул (последовательно по главам)
Для каждой главы:
1. Извлечь из `theory_clean/chapX.md` последовательность номеров и контекст («где …», ссылки
   на предыдущие формулы, табличные коэффициенты).
2. Восстановить LaTeX-запись (как для 1.1–1.3) и прислать вам на утверждение ПЕРЕД кодированием —
   т.к. часть формул многовариантна (разные схемы нагружения).
3. После утверждения — реализация + тесты.
Порядок приоритетов (по ценности для МКЭ-ядра):
   P1: 2.7 (теории прочности → оценка полей σ от МКЭ), 2.10 (усталость → ресурс),
       3.1 (тензорные соотношения), 2.2–2.5 (калибровка/аналитика для верификации МКЭ)
   P2: 2.6, 2.8, 2.9, 3.4.1–3.4.2 (колебания: собственные частоты, резонанс)
   P3: 3.2 (контакт), 3.3 (приближенные методы), 2.3, 2.11–2.12 (БД/критерии)

### Этап 2. Реализация (соглашения)
- Все функции векторизованы (NumPy), работают на полях `(n_nodes,)` и `(n_nodes, 6)` (МН-тензор);
  тяжёлые циклы — numba-опционально (декоратор fallback, если numba нет).
- Общие примитивы в `core/`: интегралы (trapezoid/cumtrapz/quad), свёртки (FFT),
  обратные функции (brentq), кусочно-линейные таблицы материалов (interp1d),
  накопление усталостных повреждений (Майнер), обработка гистограмм нагружения.
- Размерности/единицы: конвенция SI+МПа (Н, мм, МПа) — зафиксировать в README; все входные
  докстринги содержат размерность (в тексте учебника они смешанные).
- Каждый модуль: докстринг с LaTeX-формулой и ссылкой «(2.10.37)», unit-тест против аналитики,
  где возможно — против textbook-примеров из того же файла (в главах есть числовые примеры —
  использовать их как golden-тесты).

### Этап 3. Тесты и верификация
- Порталу 38 существующих тестов добавить: числовые примеры учебника (примеры с решениями
  присутствуют почти в каждой главе — извлекаются из текста автоматически).
- Инварианты: суммы вероятностей = 1, согласованность теорий прочности (при σ₂=σ₃ → 2.7↔2.2),
  предельные случаи (тонкий цилиндр 2.8 → формула Ламера), симметрия тензоров 3.1.
- Бенчмарки CI: поле 10⁶ узлов через весь пайплайн < 2 с (кроме MC).

### Этап 4. Интеграционный сценарий (Definition of Done)
Поле МКЭ (σ_von Mises по узлам) → теории прочности (2.7) → концентраторы/коэф. влияния (2.10)
→ гистограмма нагружения → повреждение по Майнеру → вероятность безотказной работы (1.3)
→ коэффициент запаса/ресурс. Прогоняется как end-to-end тест.
