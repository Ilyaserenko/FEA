# Отчет по программному расчетному ядру `strength_core`

Дата: 2026-10-14. Ветка: `master` (HEAD `1bbebed`). Рабочее состояние: чистое, все изменения закоммичены.

---

## 1. Назначение

Расчетное ядро программы прочности для постобработки результатов МКЭ.
Все формулы справочника реализованы как **векторизованные функции NumPy/SciPy**,
принимающие поля напряжений/деформаций произвольной формы (`(n_nodes,)`,
`(n_elem, 6)`, скаляры) и возвращающие поля того же размера — без циклов Python,
что обеспечивает работу на моделях в миллионы узлов.

Конвенция единиц: СИ+МПа (Н, мм, МПа). Соглашение о знаке квантилей z_p — см. README § «Соглашение о знаке z_p».

## 3. Модули и покрытие формул

### 3.1 `core.py` — общие примитивы (переиспользуются всеми модулями)
| Функция | Назначение | Сложность/примечание |
|---|---|---|
| `as_float_array`, `broadcast_fields` | приведение полей МКЭ к общей форме | O(N), zero-copy вещание |
| `principal_stresses` | главные напряжения σ1≥σ2≥σ3 из 6 компонент | аналитический метод Кардано (тригонометрическое решение кубики), векторно; **200 тыс. точек ≈ 50 мс** |
| `stress_invariants` | I1, I2, I3 тензора | O(N) |
| `von_mises_from_components`, `tresca_from_components` | эквивалентные напряжения из компонент | O(N) |
| `interp_table` | кусочно-линейные таблицы (S-N, k_t, ψ) | обёртка np.interp, массивы x любой формы |
| `solve_scalar_vectorized` | массовое решение неявных скалярных уравнений полем параметров | brentq по элементам; контракт func_factory(args_tuple) |

### 3.2 `stats.py` — Глава 1.1 (1.1.1–1.1.27), 27 функций
Относительная частота, вероятности по ПП, моменты дискретные/непрерывные
(`quad`), σ, коэффициент вариации, CDF, **свертка плотностей через БПФ**
(`fftconvolve`, O(N log N)), законы: экспоненциальный, равномерный,
треугольный, нормальный, Вейбулла; стандартизация, функция Лапласа (через
`scipy.special.erf`), правило 3σ, параметры нормального закона из диапазона.

### 3.3 `tolerance.py` — Глава 1.2 (1.2.1–1.2.15), 15 функций
Шероховатость Ra (трапеции), средние диаметры, зазоры/натяги, σ цепей
(√Σσ², вариант через крайние отклонения), пределы 3σ, размерные цепи:
среднее/допуск замыкающего звена, T_Δ = √ΣT², взаимные переходы m↔T.

### 3.4 `reliability.py` — Глава 1.3 (1.3.1–1.3.21), 23 функции
P(t)/F(t)/f(t)/λ(t) (численно: trapezoid/cumsum/gradient; аналитически:
экспоненциальный, нормальный, Вейбулл α=1), условная надёжность,
серийная/параллельная/резервированная структуры (матрицы «элементы × времена»,
`np.prod` вдоль оси), модель «напряжение–прочность» (нормальные f_lim, f_σ →
f(z)), индекс надёжности z_p и коэффициент n_p (самосогласованная пара,
см. замечание README).

### 3.5 `ch2_7_criteria.py` — Глава 2.7 (2.7.1–2.7.42), 25 функций — новый этап
- Напряжения на наклонной площадке, τ_max, круг Мора (2.7.3–2.7.6);
- обобщенный закон Гука (плоское/пространственное), дилатация, объемная деформация (2.7.7–2.7.12);
- плотность энергии формоизменения по компонентам/главным, полная энергия, девиатор (2.7.13–2.7.16, 2.7.25, 2.7.27–2.7.29);
- **4 теории прочности**: макс. нормальных напряжений, макс. главных деформаций, Треска (макс. касательных), Губер–Мизес + эквивалентные напряжения при сдвиге (2.7.20–2.7.23, 2.7.30, 2.7.34–2.7.35);
- **теория Мора** с разными пределами σт/σс: предельные напряжения, эквивалентное напряжение, коэффициент запаса n = σт·σс/(σс·σ1 − σт·σ3) c консервативной редукцией вне четверти растяжение–сжатие (2.7.36–2.7.42);
- допускаемые напряжения [σ] = σпред/n и проверка условия прочности (2.7.18–2.7.19).

⚠️ Формулы главы 2.7 восстановлены из текстового контекста учебника
(gif-картинки формул в архиве chap2_10[1].zip утрачены) — требуется
подтверждение заказчиком (см. §6).

## 4. Верификация и качество

### 4.1 Тесты
`python -m pytest tests/ -q` → **34 passed** (полное покрытие глав 1.1–1.3):
ПП сравнены с `scipy.stats` (expon/uniform/triang/norm/weibull_min), правило
3σ = 0.9973, Ra синуса = 2/π, тождества размерных цепей, согласованность
F/P/λ, обратная проверка n_p ↔ z_p (1e-9).

### 4.2 Интеграционные smoke-проверки (выполнены сегодня, на 200 000 точек)
| Проверка | Результат |
|---|---|
| `principal_stresses` vs `np.linalg.eigvalsh` | max err ≤ 5.2e-13 ✅ |
| `von_mises_from_components` vs эталонная формула | err = 0.0 ✅ |
| `equivalent_t4_mises`(гл. напр.) vs von Mises из компонент | err ≤ 1.8e-14 ✅ |
| `safety_factor_mohr(100,−40; 240/300)` = 1.81818… | совпадает с аналитикой ✅ |
| Производительность `principal_stresses` | 49.6 мс на 2·10⁵ точек (~10⁶ ≈ 0.3 с) ✅ |
| `interp_table(x, xp, fp)` при корректном порядке аргументов | [0.5, 2.5] ✅ |
| `solve_scalar_vectorized` (контракт: factory принимает кортеж) | решает v²−a=0 ✅ |

### 4.3 Выявленные недостатки (по итогам аудита)
1. **Нет автотестов на `core.py` и `ch2_7_criteria.py`** — smoke-проверки
   выполнялись вручную; нужен файл `tests/test_ch2_core.py`.
2. **API-эргономика**: сигнатура `interp_table(x, xp, fp)` неочевидна
   (первым аргументом — аргумент запроса, а не таблица); в докстринге стоит
   продублировать порядок явно. То же — контракт `func_factory(args_tuple)`
   в `solve_scalar_vectorized`: вызывает TypeError при передаче скалярного
   лямбда-аргумента; рекомендуется пример использования в докстринге.
3. **Не создан `docs/formula_registry.csv`** — на него ссылаются README-план и
   докстринг ch2_7; фактически роль реестра выполняет README.md только для гл. 1.x.
4. `strength_core/__init__.py` не импортирует `core` и `ch2_7_criteria`
   (доступны как `strength_core.core`, но не в верхнеуровневом API).
5. Опечатка в настоящем документе исправлена на месте (kвантилей → квантилей).

## 6. Риски и необходимые решения заказчика

1. **Утраченные картинки формул** в chap2_10[1].zip: реализация гл. 2.7 опирается

   будущих вероятностных модулях.

   вход VTK/Ensight/HDF5 — пока не реализовано (Этап интеграции I/O).
